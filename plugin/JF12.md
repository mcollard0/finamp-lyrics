# Jellyfin 12 support, testing, and host upgrade

Plugin 2.0.0.0 targets .NET 10 and Jellyfin 12.0. It was tested on Linux with
Jellyfin 12.0 and 12.1. Plugin 1.0.3.0 is the separate .NET 9 build for 10.11.11.
Both use the same C# implementation. The Python worker now uses the supported
`Authorization: MediaBrowser ... Token="..."` header: Jellyfin 12 disables legacy
`X-Emby-Token` authentication by default. Update an externally installed worker
as well as the plugin DLL when migrating.

## Results and limits

The builds passed 39 plugin checks each and the worker passed 72 Python tests.
Disposable Docker tests migrated actual test-server data from 10.11.11 to both
12.0 and 12.1, installed the 2.0.0.0 ZIP through Jellyfin's catalog API, checked
its checksum and extracted files, and verified Active status and settings links.
The plugin launched its real Python child worker on synthetic audio, uploaded
fixture Genius lyrics, and retrieved them through Jellyfin after migration.
Earlier lyrics, SQLite job state, and plugin settings survived.

A separate 10.11.11 → 12.1 test copied one authorized library MP3 into the
temporary test library. It used a real Genius token and the unmodified worker,
retrieved real lyrics before and after migration, uploaded them, and verified
nonempty lyrics through Jellyfin's lyric API. Production Jellyfin credentials,
database, settings and media files were not modified. Test data and containers
were removed. This validates the plugin/worker path; Finamp's on-device display,
other plugins, large-library migration and music-discovery are separate checks.
Future 12.x releases should run the same tests before claiming compatibility.

## Repeat the container test

Build the packages and runtime images using [RELEASE.md](RELEASE.md). From the
repository root, using an authentic previous 1.0.1.0 ZIP:

```bash
python3 plugin/catalog_smoke.py \
  --server-line 12 --release plugin/artifacts/release-12 \
  --server-version 12.1 --image finamp-lyrics-smoke-runtime:12.1 \
  --upgrade-from-image finamp-lyrics-smoke-runtime:10.11.11 \
  --previous-archive /path/to/finamp-lyrics-1.0.1.0.zip
```

This uses synthetic audio and fixture Genius responses on an internal Docker
network. No host ports are published. To test a real provider request, append:

```text
--live-media /path/to/authorized-song.mp3
--genius-credentials-file /path/to/credentials.json
```

Live mode copies one song twice, reads only `GENIUS_CLIENT_ACCESS` for the worker,
creates its own disposable Jellyfin account/token, and permits outbound traffic
to Genius. The source media is never mounted writable. With a service-owned
credential file, the helper can read the Genius field using `sudo -n -u jellyfin`;
otherwise run as a user able to read that file. Tokens and lyric text are not
printed or included in the result JSON. Live checks depend on provider access
and successful matching. Results are in ignored `plugin/artifacts/release-12/`.

## Upgrade an existing Arch host with the historical 10.11 pin

These commands apply to the standard paths used by the historical installer.
Inspect your service and paths first. Do not use `plugin/install.py` for this
upgrade: that helper pins 10.11.11. If 12.1 packages are already installed but
the service still runs the pinned server, no package upgrade is needed.

Jellyfin 12 rewrites database data. Its [release instructions](https://jellyfin.org/posts/jellyfin-release-12.0/)
require an offline backup, removal of incompatible third-party plugins, checking
for usernames differing only by case, and a full library scan after migration.
Allow migration to finish; a small container test does not predict the duration
on a large library. Confirm package versions and dependency availability:

```bash
pacman -Q jellyfin-server jellyfin-web
systemctl cat jellyfin.service
sudo -u jellyfin /usr/bin/python3 -c 'import requests, bs4'
```

Run the following from this repository root when ready for downtime. Stop the
listed worker/timer units that exist on your installation, and any other writers
to Jellyfin or its lyric state, before backing up. Keep the backup path printed
below; it is needed for recovery. The backup contains credentials and stays private.

```bash
sudo systemctl stop finamp-lyrics-batch.timer music-discovery.timer music-discovery-lyrics.timer
sudo systemctl stop finamp-lyrics-continuous.service finamp-lyrics-batch.service music-discovery.service music-discovery-lyrics.service
sudo systemctl stop jellyfin.service
sudo install -d -m 0700 /var/backups
jf12_backup=$(sudo mktemp -d /var/backups/jellyfin-before-12.XXXXXXXX)
printf '%s\n' "$jf12_backup"
sudo cp -a --reflink=auto /var/lib/jellyfin "$jf12_backup/data"
sudo cp -a /etc/jellyfin "$jf12_backup/config"
sudo cp -a /etc/systemd/system/jellyfin.service.d "$jf12_backup/service-overrides"
```

Check every copy succeeded before continuing. Ensure adequate backup disk space.
Move old plugin directories aside while retaining their shared configuration XML:

```bash
sudo install -d -m 0700 "$jf12_backup/disabled-plugins"
for jf12_plugin in /var/lib/jellyfin/plugins/*; do
  [ -d "$jf12_plugin" ] || continue
  [ "$(basename "$jf12_plugin")" = configurations ] && continue
  sudo mv -- "$jf12_plugin" "$jf12_backup/disabled-plugins/"
done
```

Install the prepared 12.x build and update the historical stable worker path.
Existing credentials, settings and state remain in place:

```bash
(cd plugin/artifacts/release-12 && sha256sum -c finamp-lyrics-2.0.0.0.zip.sha256)
sudo install -d -o jellyfin -g jellyfin '/var/lib/jellyfin/plugins/Finamp Lyrics_2.0.0.0'
sudo unzip plugin/artifacts/release-12/finamp-lyrics-2.0.0.0.zip -d '/var/lib/jellyfin/plugins/Finamp Lyrics_2.0.0.0'
sudo chown -R jellyfin:jellyfin '/var/lib/jellyfin/plugins/Finamp Lyrics_2.0.0.0'
sudo install -m 0644 lyrics_fetcher.py /var/lib/jellyfin/finamp-lyrics/lyrics_fetcher.py
sudo mv /etc/systemd/system/jellyfin.service.d/finamp-lyrics.conf "$jf12_backup/"
sudo systemctl daemon-reload
systemctl cat jellyfin.service
sudo systemctl start jellyfin.service
sudo journalctl -u jellyfin.service -f
```

The key change is moving only the historical `finamp-lyrics.conf` override out
of the unit directory, allowing the packaged server/web to start. Other overrides
remain. If the effective unit still pins a server, resolve that before starting.
Use Ctrl+C to leave the journal viewer; this does not stop the server.

After migration, verify the version and the plugin in Dashboard → Plugins:

```bash
curl --fail --silent http://localhost:8096/System/Info/Public
```

Run a full library scan, hard-refresh the web client, and play a song needing
lyrics. Confirm stored lyrics in Jellyfin and reload the track in Finamp if it
was already cached. Reinstall only 12-compatible third-party plugins; Bookshelf's
features moved to the server and new book metadata providers. Resume lyric batch
jobs only after the updated worker succeeds. Keep music-discovery and its lyric
bridge stopped until their database/API compatibility with 12 is verified.
The continuous worker was a transient unit; restart it with its original command
after validation rather than assuming a stopped transient unit can be restarted.

Rollback requires stopping Jellyfin and all writers, restoring the full offline
data/config backup and the saved 10.11 service override, then daemon-reloading
before starting. Do not point 10.11 at the migrated database. See Jellyfin's
[upgrade/downgrade guidance](https://jellyfin.org/docs/general/testing/upgrades/).
These instructions prepare a local test; release publication follows user testing.
